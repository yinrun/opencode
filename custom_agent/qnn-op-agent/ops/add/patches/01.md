### Execution
First attempt via `qnn-runner_run_custom_op_on_device` failed: "Context Creation failure".
Root cause: the runner's qnn-net-run command only registers ARM stub on `:HTP`,
without registering on `:CPU` and without passing `--config_file`. Per L2, both are needed.

Working command (run manually):
```bash
cd /data/local/tmp/qnn_op_test && \
export LD_LIBRARY_PATH=/data/local/tmp:/data/local/tmp/qnn_op_test:$LD_LIBRARY_PATH && \
export ADSP_LIBRARY_PATH="/data/local/tmp/qnn_op_test/htp;/data/local/tmp;..." && \
/data/local/tmp/qnn-net-run \
  --backend /data/local/tmp/libQnnHtp.so \
  --model /data/local/tmp/qnn_op_test/libQnnAddModel.so \
  --input_list /data/local/tmp/qnn_op_test/input_list.txt \
  --output_dir /data/local/tmp/qnn_op_test/output \
  --op_packages /data/local/tmp/qnn_op_test/libQnnHtpAdd.so:HEAddPackageInterfaceProvider:CPU,/data/local/tmp/qnn_op_test/htp/libQnnHtpAdd.so:HEAddPackageInterfaceProvider:HTP \
  --use_native_input_files --use_native_output_files \
  --config_file /data/local/tmp/qnn_op_test/net_run_config.json
```

Output: `Composing Graphs → Finalizing Graphs → Executing Graphs → Finished Executing Graphs` (no error).

## What I learned
- L3 candidate: For 2-input element-wise ops, `DEF_TENSOR_PROPERTIES` takes the
  Op pattern with all input names: `Op("HEAdd", "in0", "in1")`. Using just `"*"`
  works for single-input ops (silu) but the 2-input form requires explicit names.
- Runner gap: `qnn_runner_server.run_custom_op_on_device` doesn't register
  `:CPU` and doesn't pass `--config_file`, so it fails for ops that need backend
  extensions config (graphs entry). Workaround used here: run qnn-net-run
  manually after the runner has pushed all artifacts. Not patching the runner
  since instructions forbid touching `mcp_servers/` for this task.
