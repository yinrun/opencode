# mul iter 01

## Assumptions
- 同 add 复用结构，naive `a*b` 标量循环 + Tensor/PlainFloat/PlainFloat16 三 variants
- shape [1,1,128,896] fp16，2 输入 element-wise

## Steps
1. 写 src/HEMul.cpp + src/HEMulInterface.cpp（克隆 HEAdd, kernel 改 a*b）
2. Makefile：PACKAGE_NAME=HEMulPackage, LIBRARY_NAME=libQnnHtpMul.so
3. 三目标 build 全部 success（hexagon-v81 / aarch64-android / x86_64-linux-clang）
4. `qnn-runner_build_single_op_model` 生成 model.so（HEMul_graph）
5. `qnn-runner_run_custom_op_on_device` 失败但 push 文件
6. 设备上 `htp_config.json` 是上一次跑 sub 留下的旧文件（graph_names: HESub_graph）→ composeGraph 找不到 HEMul_graph
7. 写 ops/mul/build/device_configs/{net_run_config,htp_config}.json，push 后正确
8. 手动 `qnn-net-run` 双注册 CPU/HTP + `--config_file` + `--use_native_input_files --use_native_output_files`
9. pull `output_native.raw`

## Result
- cosine = 1.0000000000000002
- max_abs_err = 5.96e-8
- relative_err = 1.19e-6
- **PASS** (cosine ≥ 0.999, max_abs ≤ 1e-3)
- 1 iteration

## Lesson
- Runner 的 `htp_config.json` 是上一次 op run 时 push 的，**graph_name 会与本 op 不一致**。设备上有 stale htp_config 时 composeGraph 报 "unable to find graphName"。每个 op 必须自己写 device_configs 并 push（或者每次手跑 net-run 前清理）。
