# Patch 01 — HESoftplus close-out

Full-domain unary, kernel uses numerically-stable form to avoid `expf` overflow at large `x`:
```cpp
float ax = fabsf(xv);
float pos_part = (xv > 0.0f) ? xv : 0.0f;
out(n,h,w,d) = pos_part + log1pf(expf(-ax));
```
This is mathematically equivalent to `log(1+exp(x))` but never evaluates `expf` on positive arguments,
so it stays finite for all fp16 inputs (including x ≈ 65000).

Result: cosine=0.9999999999997919, max_abs=4.88e-4 (~4 fp16 ULP), [1,1,128,4864], 1 iteration.

Slightly larger error than tanh/sigmoid (2 ULP) because the kernel does 4 fp32 ops
(`fabsf`, `expf`, `log1pf`, add) before the final fp16 round, whereas numpy reference
uses `np.log1p(np.exp(x))` (3 ops). Still well below 1e-3 acceptance threshold.
