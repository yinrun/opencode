# Patch 03 — Sentinel test conclusively proves kernel bypass

## Date  
2026-05-28

## Test
Set kernel body to write constant `7.0f` for every output element.

## Result
Output contains zero instances of 7.0:
- Only two unique values: `[0.0, 2.4375]`
- Alternating pattern `[0.0, 2.4375, 0.0, 2.4375, ...]`
- Range `0.0..2.4375` (vs expected all `7.0`)
- Match count `0/622592`

## Conclusion
Our HVX kernel is **definitively bypassed on Hexagon device**, despite:
- Host-side verbose log shows package loaded and op TypicalOp built
- ARM stub `.so` loads via --op_packages (no dlopen error)
- Hexagon `.so` is in ADSP_LIBRARY_PATH

The bypass is independent of:
| Variable | Tested | Result |
|---|---|---|
| Path: runtime QnnModel | yes | bypass |
| Path: offline ctx-binary | yes | bypass |
| Op name: HESiLU | yes | bypass |
| Op name: HESiLU.fp16 | yes | bypass |
| Variant: Tensor | yes | bypass |
| Variant: PlainFloat16Tensor | yes | bypass |
| Variant: dual w/ HVX flag | yes | bypass |
| validateOpConfig: success | yes | bypass |
| validateOpConfig: fail | yes | bypass |

## Most likely root cause
Hand-written op-package missing required HTP registration markers that `qnn-op-package-generator` would scaffold. The Hexagon `.so` loads but doesn't register its kernel functions with HTP's dispatcher.

## Why this isn't fixable in this session
1. `qnn-op-package-generator` requires Python `lxml` package not present in env
2. Without scaffold, can't compare canonical-generated vs hand-written
3. Need to compile, push, and run a known-working canonical Relu-fp16 example end-to-end as control before attempting silu
